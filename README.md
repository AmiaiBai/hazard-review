# 隐患识别结果专家评分器

把 AI 眼镜巡检识别出的隐患，交给专家**在手机上逐条打分**，服务端自动汇总出统计页和 Excel 报告。

> ✅ **本仓库只含代码**：`data/`（真实业务数据与现场照片）已在 `.gitignore` 中整体排除，
> 克隆后需要自己准备。动手前请先读 [SECURITY.md](SECURITY.md)。

---

## 它解决什么问题

AI 眼镜自动识别出隐患（配电箱箱门未关闭、消防通道堆物……），但**识别结果本身需要人工校验**：  
隐患真的存在吗？描述和画面一致吗？引用的法规条款套得对吗？

这套工具让专家在手机上用「左滑认可 / 右滑评分」的方式快速过完一批隐患，  
并从四个维度打分，最后自动算出：

- **识别质量**：查准率 / 召回率、混淆矩阵、严重度加权漏检
- **评分口径**：各维度均分与分布、阈值敏感性曲线
- **评价人一致性**：双评覆盖率、判定一致率、Cohen's κ、分歧最大的隐患
- **对标质量**：按引用标准分组看依据适用性与引用准确性，列出需人工复核的条目

## 快速开始

**零依赖**：只用 Node 内置的 `http` / `fs` / `path` / `crypto` / `zlib`，不需要 `npm install`。

```bash
node server.js
```

- 手机端（评分）：<http://localhost:3000>
- 管理端（统计）：<http://localhost:3000/admin>
- 管理员密码：**代码里没有默认密码**。首次运行会随机生成一个，
  **打印在启动日志里**，同时写入 `data/admin.json`；换密码就改这个文件，
  **下一次登录即生效**（服务端每次登录都重读该文件，不用重启）。
  部署时也可以先用环境变量 `HR_ADMIN_PW` 指定。

> 仓库不含数据（见 [SECURITY.md](SECURITY.md)），所以克隆后是空跑的：
> 首次启动会自动建 `data/`，把识别记录放成 `data/hazards.json`、
> 现场照片放 `data/images/`、缩略图放 `data/thumbs/` 才有内容。

需要局域网内其他人访问（办公室 WiFi）：

```bash
PORT=3206 node server.js        # 监听 0.0.0.0，按终端提示的局域网 IP 访问
```

Windows 下可直接双击 `start-lan.cmd`。

## 核心设计

### 单卡片牌堆：一页一条

手机上不做瀑布流。一次只显示一条隐患，**左滑认可 / 右滑评分 / 轻点看详情**，  
竖向滚动只在卡片内部发生，绝不会误开抽屉。

评完出现「筛选进度总览」：圆点阵列 + 遗漏提示 + 结果预览，点圆点可直接跳回去改。

### 评分维度（初始值 90 + 滑块）

| 维度      | 含义              |
| ------- | --------------- |
| 隐患真实性   | 画面中是否确实存在这条隐患   |
| 隐患描述符合性 | 描述内容是否与画面事实一致   |
| 法规依据适用性 | 引用条款是否适用于该隐患    |
| 依据引用准确性 | 引用条款是否适用于该区域、行业 |

### 分层鉴权

「部门 / 检查人 / 评审人姓名」属于同一类信息，由**页面顶部一个解锁入口**统一控制：

- 鉴权做在**接口层**（非管理员拿到的响应里，这些字段已被服务端递归脱敏，不是前端藏起来）
- 评审人姓名换成「评审人N」代号，**按姓名排序编号**（不按评分条数，否则代号本身就是排行榜）
- 导出 Excel 同步裁列：匿名 11 张表，管理员 12 张（多一张「部门汇总」）
- 令牌存 sessionStorage，服务端 TTL 12 小时，**服务重启全部失效**（前端会自愈清掉死令牌）

### 数据不引入「批次」概念

一次导入 = 一个批次，那是**导入方的操作痕迹**，使用者不关心。  
数据一律按**识别时间顺承**，时间维度只用记录的 `time`，聚合按「月份 / 周 / 日期区间」。

## 主要接口

| 方法   | 路径                      | 说明                   |
| ---- | ----------------------- | -------------------- |
| GET  | `/api/meta`             | 维度定义、初始分、检查人清单（管理员）  |
| GET  | `/api/hazards`          | 识别记录列表（预压缩 + ETag）   |
| GET  | `/api/basis`            | 法规依据全文（按需加载，列表里只带开头） |
| GET  | `/api/my`               | 当前评审人的评分与处理意见        |
| POST | `/api/submit`           | 提交评分                 |
| POST | `/api/delete`           | 撤销一条评分               |
| GET  | `/api/stats`            | 全量统计（按身份脱敏）          |
| GET  | `/api/dept-stats`       | 按部门统计（管理员）           |
| POST | `/api/admin/login`      | 管理员登录，返回令牌           |
| POST | `/api/admin/logout`     | 作废令牌                 |
| GET  | `/api/export.xlsx`      | 全量导出（内嵌现场图片）         |
| GET  | `/api/export-dept.xlsx` | 按部门统计清单（管理员）         |
| GET  | `/api/export.csv`       | CSV 导出               |
| GET  | `/api/raw`              | 原始提交数据（管理员，供同步脚本使用）  |
| GET  | `/api/health`           | 健康检查                 |

## 技术选择说明

- **为什么零依赖**：部署环境是工地 / 办公室的一台 Windows 机器，装不了构建链。  
  一个 `node server.js` 就能跑，比任何框架都可靠。
- **为什么用 JSON 文件而不是数据库**：数据量在千条量级，单进程写入，  
  JSON 文件可读、可 diff、可直接手工修，运维成本为零。
- **为什么手写 xlsx**：需要在单元格里内嵌现场图片，且不想引入 `exceljs` 之类的依赖。  
  `lib/xlsx.js` 直接产出 OOXML（六类部件：worksheet / sharedStrings / styles / media / drawing / rels）。
